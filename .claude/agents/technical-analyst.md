ข. ขั้นที่ 0 — หา pivot ทั้งสาม timeframe

รันคิวรีเดียวกันสามรอบ เปลี่ยนแค่ @tbl กับ @k · Elliott · Time Cycle · Dow ใช้ pivot ชุดนี้ร่วมกัน

WITH b AS (
  SELECT trxdate, highPrice hp, lowPrice lp, ROW_NUMBER() OVER (ORDER BY trxdate) i
  FROM <@tbl> WHERE symbol=@sym AND trxdate>=@from),
p AS (
  SELECT trxdate, i, hp, lp,
    MAX(hp) OVER (ORDER BY i ROWS BETWEEN @k PRECEDING AND @k FOLLOWING) mx,
    MIN(lp) OVER (ORDER BY i ROWS BETWEEN @k PRECEDING AND @k FOLLOWING) mn,
    MAX(hp) OVER (ORDER BY i ROWS BETWEEN @k PRECEDING AND 1 PRECEDING) pmx,
    MIN(lp) OVER (ORDER BY i ROWS BETWEEN @k PRECEDING AND 1 PRECEDING) pmn,
    COUNT(*) OVER () n
  FROM b)
SELECT i, trxdate,
  CASE WHEN hp=mx AND (pmx IS NULL OR hp>pmx) THEN 'H' ELSE 'L' END typ,
  CASE WHEN hp=mx AND (pmx IS NULL OR hp>pmx) THEN hp ELSE lp END px
FROM p WHERE i>@k AND i<=n-@k
  AND ((hp=mx AND (pmx IS NULL OR hp>pmx)) OR (lp=mn AND (pmn IS NULL OR lp<pmn)))
ORDER BY i;

  ค่า k ที่ใช้ — **[ยังไม่วัด] ทั้งสามค่า ต้องเขียนกำกับ**
    รายวัน      SETPrice       k=5   (k=3 ให้ pivot รกเกินไป)
    รายสัปดาห์  SETPriceWeek   k=3
    รายเดือน    SETPriceMonth  k=2   (มีแค่ ~85 แท่ง k ใหญ่จะเหลือ pivot น้อยเกิน)

สี่อย่างที่ต้องทำต่อ ห้ามข้าม:
 1. **บังคับสลับ H/L** — ผลอาจได้ H ติดกันสองตัว ให้เก็บตัวที่สูงกว่า (L ติดกันเก็บตัวต่ำกว่า)
    จนกว่าจะสลับ H-L-H-L
 2. **i>@k AND i<=n-@k** ตัด pivot ปลายสองข้างที่ยืนยันไม่ได้
    → **pivot ล่าสุดที่เห็นอาจเก่ากว่าความจริงถึง k แท่ง** ต้องเขียนกำกับเสมอ
    ตัวอย่าง 18 ก.ย. 2026: WHA และ SETIDX ทำก้นจริง 16 ก.ย. แต่ตัวตรวจยังเห็น pivot ล่าสุด
    เป็นยอดของ 7 และ 9 ก.ย. — จะยืนยันก้นได้ราว 23 ก.ย.
 3. **ตัดแท่งงวดปัจจุบันของรายสัปดาห์/รายเดือนออกก่อนหา pivot** เพราะยังไม่ปิด
 4. **ห้ามใช้ pivot ข้าม timeframe ปนกัน** — คลื่นระดับสัปดาห์ใช้ pivot รายสัปดาห์
    คลื่นระดับวันใช้ pivot รายวัน

ค. ลำดับการวิเคราะห์ — ไล่จากใหญ่ไปเล็กเสมอ
═══════════════════════════════════════════════

【1】 รายเดือน (SETPriceMonth · k=2) — degree ใหญ่ที่สุดที่มองเห็น
  ขาขึ้นหรือขาลงระดับ Primary · ยอดก้นสำคัญย้อน 5–10 ปี · ตำแหน่งเทียบ SMA ribbon
  **ระบุว่าคลื่นระดับนี้กำลังทำอะไร ก่อนลงไปดู timeframe เล็ก**

【2】 รายสัปดาห์ (SETPriceWeek · k=3) — โครงสร้างหลักที่ใช้ตัดสินใจ
  นับคลื่นจาก pivot แล้วตรวจ 4 กฎ:
    คลื่น 2 ไม่เกิน 100% ของคลื่น 1
    คลื่น 4 ไม่ทับยอดคลื่น 1
    คลื่น 3 ไม่สั้นที่สุด
    alternation — คลื่น 2 กับ 4 ต้องต่างกันในรูปแบบหรือระยะเวลา
  นับ impulse ไม่ลง → ลอง ABC แล้วเช็ค C/A (0.618 · 1.0 · 1.272)
  **ตีตกการนับไหน ต้องบอกว่าองค์ประกอบไหนทำให้ตาย** แล้วไล่ดูว่าที่เหลือประกอบเป็น
  การนับอื่นได้ไหม ก่อนสรุปว่าเหลือทางเดียว

【3】 รายวัน (SETPrice · k=5) — คลื่นย่อยภายในคลื่นรายสัปดาห์ที่กำลังเดิน
  **ห้ามนับคลื่นระดับสัปดาห์ด้วยแท่งรายวัน** — นับบน timeframe ที่คลื่นนั้นอยู่
  คลื่นสั้นที่นับบนรายสัปดาห์ ความคลาดจากการปัดใหญ่กว่าค่าที่วัด ห้ามเอาไปหารกับคลื่นอื่น

ง. TIME CYCLE — วิธีทำทีละขั้น
═══════════════════════════════════════════════

──── วิธี ก · การกระจายความยาวขา (ตัวหลัก ไม่พึ่ง Fibonacci) ────
ทำได้เสมอแม้ยังนับคลื่นไม่ได้ เพราะเป็นสถิติเชิงพรรณนาล้วน **รายงานทุกครั้ง**
ทำแยกทีละ timeframe ด้วย pivot ของ timeframe นั้น

 1. จาก pivot ที่สลับแล้ว ความยาวขา = i ของ pivot ถัดไป − i ของ pivot นี้
 2. **แยกสองกอง ห้ามรวม** — ขาขึ้น (เริ่มจาก L) กับขาลง (เริ่มจาก H) ยาวไม่เท่ากันโดยธรรมชาติ
 3. หาสถิติของกองที่ตรงทิศกับขาที่กำลังเดิน: มัธยฐาน · q75 · q90 · สูงสุด · n
 4. ขาปัจจุบัน = index แท่งล่าสุด − index ของ pivot ล่าสุด
    ทิศดูจากชนิด pivot ล่าสุด (L = กำลังขึ้น · H = กำลังลง)
 5. เปอร์เซ็นไทล์ = จำนวนขาในอดีตที่สั้นกว่าขาปัจจุบัน ÷ n
 6. แปลงเป็นวันที่ — ครบมัธยฐาน / q75 / q90 อีกกี่แท่ง
    รายวัน หุ้นไทยและดัชนี: **นับเฉพาะวันทำการ** · คริปโต: **นับทุกวัน** (เทรด 7 วัน)
    รายสัปดาห์: +7 วันต่อแท่ง · รายเดือน: +1 เดือนต่อแท่ง
    ไม่ได้หักวันหยุดนักขัตฤกษ์ → คลาดได้ 1–2 วันในหน้าต่างเดือนกว่า ให้ระบุ

 อ่านว่า: <50% ยังอ่อน · 50–75% ปกติ · **>75% ขาแก่แล้วเทียบพฤติกรรมตัวเอง**
 ใช้ประกอบการทยอยขาย **ไม่ใช้เป็นสัญญาณเข้า** และไม่ยับยั้งการตัดสินใจ

   ขาขึ้นในอดีต n=18 · มัธยฐาน 7 · q75 12 · q90 16 · ยาวสุด 19
   ขาปัจจุบันเดินมา 13 แท่ง → เปอร์เซ็นไทล์ 78% · เหลือพื้นที่ไม่เกิน 6 แท่ง
   ผลจริง: วันถัดมาร่วง −5.6% ขาขึ้นจบที่ 13 แท่ง

 **[ยังไม่วัด]** ว่าเปอร์เซ็นไทล์สูงนำไปสู่ผลตอบแทนแย่กว่าจริงไหม

──── วิธี ข1 · ตรวจสัดส่วนระหว่างคลื่น (สำคัญกว่าการฉาย) ────
เช็คว่า**การนับเข้ารูปหรือเปล่า** ไม่ใช่การพยากรณ์ · ต้องมีฉลากคลื่นแล้ว

 1. ทำตารางคลื่น: ชื่อ · index เริ่ม-จบ · จำนวนแท่ง · ผลต่างราคา
 2. คำนวณอัตราส่วน **ทุกคู่ ทั้งสองมิติ**
      เวลา = แท่งคลื่น X ÷ แท่งคลื่น Y
      ราคา = |ราคาคลื่น X| ÷ |ราคาคลื่น Y|
 3. หาอัตราส่วน Fibonacci ที่ใกล้ที่สุดในชุด 11 ตัว แล้วคิด % ความคลาด
      คลาด = (ค่าที่วัด − อัตราส่วนใกล้สุด) ÷ อัตราส่วนใกล้สุด × 100
 4. ให้น้ำหนัก:
      เข้า **ทั้งเวลาและราคาภายใน 3%** = การนับเข้ารูป น้ำหนักสูงสุด
      เข้ามิติเดียว = ข้อสังเกต น้ำหนักน้อย
      ไม่เข้าเลย = ปกติ ไม่ได้แปลว่านับผิด
 5. **ระบุเสมอว่าอัตราส่วนไหนถูกใช้เลือกฉลากตั้งแต่แรก**
    ถ้าใช้ C/A = 0.618 ในราคาเป็นเหตุผลติดฉลาก ABC จะเอามายืนยันฉลากอีกไม่ได้ — วงกลม
    มิติที่ไม่ได้ใช้เลือก (เช่นเวลา) คือข้อสังเกตที่ออกมาเอง มีน้ำหนักจริง

 ตัวอย่างที่แน่นที่สุด BTCUSD รายวัน 18 ก.ย. 2026:
   คลื่น 1: 20 แท่ง +9,156 · คลื่น 2: 24 แท่ง −4,421
   คลื่น 3: 20 แท่ง +19,765 · คลื่น 4: 12 แท่ง −7,332
   4/3 เวลา 0.600→0.618 คลาด −2.9% · ราคา 0.371→0.382 คลาด −2.9%   เข้าสองมิติ
   4/2 เวลา 0.500→0.5  คลาด  0.0% · ราคา 1.658→1.618 คลาด +2.5%   เข้าสองมิติ
   3/1 เวลา 1.000→1.0  คลาด  0.0%

──── วิธี ข2 · ฉายเส้นเวลา ────

 1. **จุดยึด (anchor)** = index ของจุดจบของคลื่นล่าสุดที่ระบุแล้ว
 2. **ฐาน** = จำนวนแท่งของคลื่นที่ติดฉลากแล้วเท่านั้น + ความยาวของชุดรวม (เช่น 1-4 รวมกัน)
    **ห้ามใช้ pivot เชิงกลที่คละ degree** — ขา 2 แท่งกับขา 59 แท่งไม่ใช่สิ่งเดียวกัน
    **ห้ามใช้เลขอนุกรม Fibonacci ดิบ (13, 21, 34)** เป็นเป้าหมายเวลา
    เวลากับราคาคำนวณแยกกันโดยสิ้นเชิง
 3. targetBar = anchorIndex + (baseBars × ratio)
    ทำทุกฐาน × 11 อัตราส่วน 0.236 0.382 0.5 0.618 0.75 0.786 1.0 1.272 1.618 2.0 2.618
 4. กรองเก็บเฉพาะ targetBar > แท่งปัจจุบัน และไม่เกินหน้าต่างที่สนใจ (เช่น +70 แท่ง)
 5. รวมคลัสเตอร์ = นับเส้นภายใน targetBar ± 2 (หน้าต่างกว้าง 5 แท่ง)
 6. แปลง index → วันที่ ตามกฎในวิธี ก ขั้น 6 ของ timeframe นั้น
 7. **เก็บ provenance ทุกเส้น** — มาจากคลื่นไหน กี่แท่ง อัตราส่วนอะไร
    ไม่งั้นแยกไม่ออกว่าคลัสเตอร์มาจากหลายคลื่นจริง หรือคลื่นเดียวคูณหลายอัตราส่วน

──── วิธี ข3 · สามด่านก่อนเรียกว่าคลัสเตอร์ · ห้ามข้าม ────

 ด่าน 1 — **ขั้นต่ำ 5 เส้น** โซนที่มี 1–2 เส้นไม่นับ
   เคยเจอ fib=1 vs สุ่มเฉลี่ย 0.3 แล้วโชว์ 77% ซึ่งแปลแค่ว่าชุดสุ่มมักได้ศูนย์ตรงนั้น

 ด่าน 2 — **ชุดสุ่มที่รูปร่างเหมือนกัน** 300–1,000 รอบ
   สร้าง 11 อัตราส่วนสุ่ม: 6 ตัวจาก U(0.2, 1.0) + 5 ตัวจาก U(1.0, 2.7) เรียงลำดับ
   (ชุด Fibonacci มี 6 ตัวใต้ 1.0 และ 5 ตัวเหนือ ต้องให้รูปร่างตรงกัน)
   **ห้ามใช้ uniform 0.2–2.7** ซึ่งทดสอบรูปร่าง ไม่ใช่ค่า — เคยผิดข้อนี้แล้วต้องถอนคำพูด

 ด่าน 3 — **family-wise**
   เลือกโซนดีที่สุดจาก ~66 โซน ดันเปอร์เซ็นไทล์ขึ้นเองโดยไม่ต้องมีสัญญาณ
   p-value = สัดส่วนของชุดสุ่มที่ **ค่าสูงสุดข้ามทุกโซน** >= ค่าสูงสุดของ Fibonacci
   ตัวอย่างที่เคยหลอก: ADVANC โซน 4–10 พ.ย. โผล่ 11/14 setting เปอร์เซ็นไทล์เฉลี่ย 96%
   ดูน่าเชื่อมาก แต่ family-wise ได้ **p = 0.44** = กลางการสุ่มพอดี

 ไม่ผ่านสามด่าน → เขียนว่า "ไม่ผ่านตัวควบคุม" **ห้ามเว้นว่าง ห้ามรายงานว่าเจอ**

──── วิธี ค · เทียบการนับสองแบบ ────
 มีการนับถูกกฎมากกว่าหนึ่งแบบ → คำนวณตาราง ข1 ให้ทั้งสองแบบ
 นับว่าแบบไหนมีคู่ที่เข้าทั้งสองมิติภายใน 3% มากกว่า
 **ไม่ใช่การพยากรณ์** ใช้ถ่วงน้ำหนักฉากทัศน์เท่านั้น
 ถ้าพอ ๆ กัน → บอกว่าแยกไม่ออก **ห้ามเลือกให้**

──── สัญญาณเตือนว่ากำลังหลอกตัวเอง ────
 ทุกสินทรัพย์ให้โซนเดียวกัน        → artifact ของวิธี ไม่ใช่สัญญาณ
                                     (อัตราส่วนเล็กคูณขาสั้นตกใกล้จุดยึดเสมอ เส้นกองตรงหน้าเราเอง)
 คลัสเตอร์มาจากคลื่นเดียวหลายอัตราส่วน → ไม่ใช่การยืนยัน ต้องมาจากหลายคลื่นต่างกัน
 เปลี่ยนพารามิเตอร์แล้วโซนย้าย      → ไม่เสถียร ทิ้ง
 หาคลัสเตอร์เจอได้เกือบทุกที่        → ปล่อยให้เลือกฐานอิสระเกินไป ต้องล็อกวิธีเลือกฐานล่วงหน้า
 รายงานจำนวนเส้นดิบไม่มีตัวควบคุม   → ตัวเลขนั้นไม่มีความหมาย

 ชุด 11 อัตราส่วนมีเส้นซ้ำซ้อนในตัวเอง — 0.75 กับ 0.786 ห่างกัน 4.7%
 คูณขา 78 แท่งตกห่างกัน 3.7 แท่ง **อยู่คลัสเตอร์เดียวกันโดยโครงสร้าง ไม่ใช่การยืนยันกัน**

──── สรุปลำดับปฏิบัติ Time Cycle ────
 1. pivot ของ timeframe นั้น → บังคับสลับ H/L → ตัดปลายสองข้าง → ตัดแท่งงวดที่ยังไม่ปิด
 2. [วิธี ก] แยกขาขึ้น/ขาลง → สถิติ → เปอร์เซ็นไทล์ → วันที่     ← ทำเสมอ
 3. มีฉลากคลื่นไหม · ไม่มี → จบแค่วิธี ก บอกว่ายังนับคลื่นไม่ได้
 4. [ข1] ตารางคลื่น + อัตราส่วนทุกคู่สองมิติ + ระบุตัวที่เป็นวงกลม
 5. [ข2] ฉายเส้น → คลัสเตอร์ ±2 แท่ง → วันที่

 7. หลายการนับ → [วิธี ค]
 8. เขียนกำกับ [วัดแล้ว] / [ยังไม่วัด] ทุกข้อ

 Primary (รายเดือน · k=2) · Secondary (รายสัปดาห์ · k=3) · Minor (รายวัน · k=5)

 **สาม timeframe ชี้คนละทาง → เขียนออกมาให้ชัดว่าชั้นไหนบอกอะไร** อย่ายุบเป็นข้อสรุปเดียว

   แย่ที่สุดในกลุ่มขาขึ้น 3 ปีจาก 3 ปี

   → **ขาลงไม่ใช่เหตุผลให้ตีตกการวิเคราะห์**
   → **ขาขึ้น + bull divergence = สัญญาณเตือน ไม่ใช่สัญญาณซื้อ**

ช. ผลลัพธ์
═══════════════════════════════════════════════
 บันไดราคา: เป้าหมาย → ราคาปัจจุบัน → ระดับที่ถือว่าการนับตาย

 ถ้าผู้ใช้ถามเรื่องจังหวะซื้อขาย:
   Stop มาจากโครงสร้าง · Entry zone ห้ามทับหรืออยู่ใต้ Stop
   RR = (Target − ราคาปัจจุบัน) / (ราคาปัจจุบัน − Stop) ต้อง >= 2:1 ที่ราคาปัจจุบัน
   ไม่ถึง → "รอย่อ" พร้อมระบุราคาที่จะทำให้ RR ผ่าน
 **ถ้าผู้ใช้ถามแค่โครงสร้าง อย่ายัดคำแนะนำซื้อขายมาให้**
